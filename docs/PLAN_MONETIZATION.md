# PTSS 수익화 계획 (Monetization & Enterprise Strategy)

이 문서는 PTSS 프로젝트의 지속 가능한 개발을 위한 수익화 전략과 기업용 라이선스 정책을 기술합니다.

## 1. 기본 원칙
- **개인 및 비영리**: 오픈소스 정신에 따라 영구 무료 제공 (`Free to Use`).
- **기업 및 상업적 목적**: 시스템의 고도화된 보안/통제 기능을 활용하는 대가로 유료 라이선스 적용 (`Paid for Business`).
- **투명성**: 후원금은 로드맵에 명시된 기업형 기능(PAM, 감사 로직 등) 개발을 위해 재투자됩니다.

## 2. 수익 창출 모델: GitHub Sponsors
별도의 사업자 등록 없이도 기업 사용자가 합법적으로 비용 처리를 할 수 있도록 **GitHub Sponsors** 플랫폼을 주력 통로로 활용합니다.

### GitHub Sponsors 활용의 이점
- **영수증 발행**: GitHub 본사 명의의 인보이스 제공 (기업의 비용 처리 가능).
- **수수료 면제**: 개인 개발자의 경우 GitHub 수수료 0% (Stripe 수수료 제외).
- **접근성**: 기업용 GitHub 계정으로 손쉽게 후원 및 구독 가능.

## 4. 유료화 대상 기업형 기능 (Roadmap 연계)
다음 기능들이 일정 수준 이상 구현되는 시점에 정식으로 기업용 유료 정책을 시행합니다.

1. **실시간 세션 녹화 및 시각적 리플레이**
2. **엔터프라이즈 명령어 방화벽 (Command Guard)**
3. **일시적 권한 승인 (JIT Access) 워크플로우**
4. **SSO/LDAP 통합 인증 체계**
5. **멀티 서버 클러스터 일괄 제어 대시보드**

## 5. 배포 모델: Dual-Path Model
PTSS는 오픈소스 커뮤니티의 성장과 기업용 솔루션의 비즈니스 안정성을 동시에 확보하기 위해 두 가지 배포 경로를 유지합니다.

### 5.1 Community Edition (Open Source)
- **대상**: 개인 개발자, 학생, 소규모 비영리 단체.
- **배포 방식**: GitHub를 통한 전체 소스 코드 공개.
- **범위**: 현재 개발된 기본 기능 (SSH 터미널, SFTP, 활동 히스토리 등).
- **주요 제약**:
  - **명령어 스니펫**: 최대 **10개**까지만 저장 가능 (맛보기 및 개인용).
- **목표**: 인지도 확산 및 오픈소스 기여를 통한 생태계 확장.

### 5.2 Enterprise Edition (Proprietary Binary)
- **대상**: 기업, 보안 감사 의무가 있는 기관, 유료 후원사.
- **배포 방식**: **난독화 및 바이너리화된 실행 파일** 형태로 제공.
- **범위 (ENT 전용 기능)**: 
  - **명령어 스니펫 무제한 저장**: 기업 내 방대한 스크립트 자산 관리 지원.
  - **사용자 명령어 제한 (Restricted Shell)**: 실시간 필터링 및 차단.
  - **세션 실시간 녹화 및 리플레이**: 보안 감사용 시각적 데이터.
  - **일시적 권한 승인 (JIT Access)**: 승인 프로세스 기반의 한시적 접속.
  - **클러스터 일괄 스크립트 배포 및 실행**: 대규모 서버 자동화 관리.
- **라이선스 정책**: 후원이 완료된 사용자(기업)를 대상으로 **별도의 라이선스 키 및 전용 바이너리 발급**.
- **특징**: 라이선스가 등록된 서버에서만 ENT 전용 기능 활성화.

## 6. 기술적 소스 보호 및 라이선스 관리
기업용 버전의 무단 복제 및 수정을 방지하기 위해 다음 기술을 적용합니다.

1. **코드 난독화 (Obfuscation)**: `PyArmor` 등을 활용하여 파이썬 로직을 암호화하고 무결성 검사를 수행합니다.
2. **바이너리 컴파일 (Native Binary)**: `Nuitka` 또는 `Cython`을 사용하여 소스 코드를 C/C++ 기반의 기계어 바이너리로 변환, 원본 소스 유출을 원천 차단합니다.
3. **하드웨어 바인딩 (Machine Lock)**: 특정 고객사의 서버 식별자(MAC, HDD ID 등)에 종속된 라이선스 키를 발행하여 무단 배포를 방지합니다.

## 7. 실행 로드맵
1. **[Phase 1]**: GitHub Sponsors 활성화 및 README 내 후원 링크 노출 (완료).
2. **[Phase 2]**: 로드맵의 '활동 히스토리' 및 '보안 강화' 기능 고도화 (진행 중).
3. **[Phase 3]**: 기업형核心 기능 개발 및 **Enterprise Edition 바이너리 빌드 파이프라인** 구축.
4. **[Phase 4]**: 정식 유료 플랜 런칭 및 기업용 전용 라이선스 관리 서버 연동.
