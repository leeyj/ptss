# PTSS 보안 및 감사 백서 (Security & Audit Whitepaper)

이 문서는 PTSS의 보안 설계 원칙과 기업용 데이터 보호 매커니즘을 상세히 설명합니다.

---

## 1. 데이터 암호화 아키텍처 (AES-256)

PTSS는 모든 민감 데이터를 **AES-256 (Fernet)** 방식으로 암호화하여 저장합니다.

### 1.1 암호화 마스터 키 (Master Key) 관리
- 서비스 초기화 시 생성되는 `PTSS_MASTER_KEY`는 원격 서버 접속 정보(비밀번호, 개인키) 암호화의 근간이 됩니다.
- 이 키는 데이터베이스의 `Config` 테이블에 저장되어 관리되며, `/setup` 단계에서 사용자가 직접 설정하거나 시스템이 자동 생성합니다.
- 보안을 위해 주기적인 키 변경과 DB 백업 관리가 권장됩니다.

### 1.2 암호화 대상 데이터
- **Host Passwords**: 원격 서버 접속용 비밀번호.
- **Private Keys**: SSH 인증에 사용되는 개인키 전문.
- **Config**: 일부 보안 민감 설정값.

## 2. 권한 기반 접근 제어 (RBAC)

사용자의 역할(Role)에 따라 기능과 데이터에 대한 접근 권한을 엄격히 분리합니다.

### 2.1 계정 권한 구분
- **Admin (관리자)**: 시스템 전역 설정, 전체 사용자 및 호스트 관리, 전체 활동 히스토리 열람 권한.
- **User (일반 사용자)**: 자신에게 할당된 서버 접속 및 본인의 활동 기록만 열람 가능.

### 2.2 히스토리 보안 (Audit Log Security)
- 일반 사용자가 API나 URL 우회를 통해 타인의 히스토리나 관리자 기록에 접근하는 행위를 서버 측에서 원천 차단합니다.
- 모든 조회 쿼리에는 현재 세션 사용자의 ID가 강제로 필터링 조건으로 포함됩니다.

## 3. 세션 및 통신 보안

### 3.1 세션 보안 키 (Secret Key) 관리
- 웹 세션(Cookie) 및 서명 보호를 위해 사용되는 `PTSS_SECRET_KEY`는 반드시 서버의 환경 변수(`.env`)에 안전하게 보관되어야 합니다.
- **물리적 분리**: 데이터(DB)와 열쇠(`.env`)를 분리함으로써, DB 파일 단독 탈취 시에도 사용자 세션을 하이재킹하거나 정보를 위조하는 행위를 원천 차단합니다.
- 서버 재시작 시에도 고정된 키를 사용하도록 설정함으로써 사용자의 작업 연속성을 보장합니다.

### 3.2 터미널 세션 보호
- 각 터미널 세션은 고유한 `Session ID`로 관리되며, 다른 세션에서의 개입을 불허합니다.
- WebSocket(Socket.io) 전송 시 세션 검증 프로세스를 거쳐 유효한 연결인지 실시간으로 체크합니다.

### 3.2 전송 계층 보안 (HTTPS/SSL)
웹 기반 SSH 시스템은 브라우저와 서버 간의 모든 통신이 암호화되어야 합니다.
- **필수 요구 사항**: 운영 환경 배포 시 반드시 **HTTPS** 프로토콜을 사용해야 합니다. HTTP 평문 통신 시 관리자 비밀번호 및 터미널 입출력 데이터가 네트워크 상에서 노출될 위험이 있습니다.
- **권장 구현**: Nginx 또는 Apache와 같은 리버스 프록시(Reverse Proxy)를 전면에 배치하고, **Let's Encrypt** 등을 통해 SSL 인증서를 적용하는 아키텍처를 권장합니다.

### 3.3 CSRF 및 해킹 방지
- Flask의 보안 설정을 통해 사이트 간 요청 위조(CSRF)를 방지합니다.
- WebSocket 통신 시에도 세션 기반 인증을 거친 연결만 허용하여 불법적인 세션 하이재킹을 차단합니다.

## 4. 개발 보안 및 자동화 (DevSecOps)

### 4.1 Git 보안 점검 (Pre-commit Hook)
코드 저장소에 민감한 정보가 유입되는 것을 방지하기 위해 자동 스캔 시스템을 운용합니다.
- **감시 항목**: 사설 IP 주소, 개인 계정 정보, 하드코딩된 비밀번호 선언, API 토큰 등.
- **실행 시점**: `git commit` 수행 시 자동으로 `tools/security_scan.py`가 실행되어 위반 사항 발견 시 커밋을 중단합니다.

### 4.2 실시간 명령어 필터링
- 시스템 관리자는 상시적으로 일반 사용자의 위험 명령어 실행을 제한할 수 있습니다.
- 백엔드 레이어에서 터미널 입력 스트림을 실시간 감시하여 금지된 키워드 탐지 시 즉각 경고 및 실행 차단을 수행합니다.

## 5. 향후 보안 고도화 (Enterprise Edition)

기업용 버전에서는 더욱 강화된 통제 기능을 제공할 예정입니다.
- **실시간 세션 녹화**: 전송되는 모든 입출력을 바이너리 형태로 기록하여 사후 복기 기능 제공.
- **명령어 방화벽**: 위험 키워드(`rm -rf` 등) 감지 시 실시간 차단 및 관리자 승인 요구.
- **JIT 권한**: 상시 권한을 제거하고, 필요 시에만 일시적으로 권한을 부여하는 체계.

## 6. 필수 환경 변수 설정 (Required .env)

운영 및 보안을 위해 설치 디렉토리의 `.env` 파일에 다음 항목이 반드시 정의되어야 합니다.

```env
# 데이터베이스 연결 정보 (기본값: sqlite:///ptss.db)
DATABASE_URL=sqlite:///ptss.db

# Flask 세션 보호용 비밀키 (임의의 긴 문자열 사용 권장)
# 이 값이 유출되거나 변경되면 모든 로그인 세션이 만료됩니다.
PTSS_SECRET_KEY=ptss_your_unique_secret_key_string
```
