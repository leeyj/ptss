# 2차 고도화 구현 계획: 보안 및 감사 로그(Audit Log) 강화

## 1. 개요
시스템의 보안성 향상을 위해 사용자별 명령어 제한(Restricted Shell) 기능을 도입하고, 시스템 내부에서 발생하는 모든 주요 액션을 사용자 단위로 추적할 수 있도록 감사 로그 시스템을 고도화합니다.

## 2. 주요 작업 단계

### Phase 1: 감사 로그(Audit Log) 스키마 고도화
- [ ] `History` 모델에 `user_id` 외래키 추가 (누가 실행했는지 기록).
- [ ] 기존 기록에 대한 마이그레이션 전략 수립 (기본값 설정).
- [ ] 액션 타입 추가: `LOGIN`, `LOGOUT`, `AUTH_FAIL`, `FILE_VIEW` 등.

### Phase 2: 사용자별 명령어 제한 (Restricted Shell)
- [ ] 관리자 패널에서 전역 또는 사용자별 '명령어 블랙리스트' 설정 기능. (예: `rm -rf`, `su`, `sh` 등 금지 단어 설정)
- [ ] 실시간 터미널 입력 필터링 로직 강화:
    - 웹소켓(`terminal_input`) 단에서 명령어 실행 전 키워드 검사.
    - 차단된 명령어 시도 시 즉시 알림 및 로그 기록(`AUTH_VIOLATION`).

### Phase 3: 통합 활동 히스토리 UI
- [ ] 관리자용 전체 활동 로그 대시보드 구현.
- [ ] 필터링 및 검색 기능:
    - 특정 기간별 조회.
    - 특정 사용자 또는 특정 호스트별 필터링.
    - 명령어 검색.
- [ ] 실시간 보안 알림 UI (실패한 접속 시도 등 강조).

### Phase 4: 대용량 출력 및 성능 최적화 (Roadmap 연계)
- [ ] 감사 로그 내역이 많아질 경우를 대비한 페이징 처리.
- [ ] 터미널 렌더링 최적화 (xterm-addon-webgl 검토).

## 3. 세부 기술 요구사항
- **DB**: SQLite 마이그레이션 (컬럼 추가) 시 데이터 유실 주의.
- **성능**: 실시간 터미널 입력 시 필터링 로직에 의한 딜레이 최소화.
- **보안**: 관리자 자신도 감사 로그를 삭제할 수 없도록 권한 분리 고려.
